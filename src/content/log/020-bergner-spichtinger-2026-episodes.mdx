## Episode 1: getting the model to run

- Useful transcript: [model extraction and Figure 4 setup](../../sessions/bs2026-figure4-model-extraction/).
- Used the `extract-model` workflow on the Bergner & Spichtinger 2026 paper
  to extract the 3-variable ODE system.
- That went smoothly, with only a little guidance needed from me.
- Replicated Figure 4 from the paper as a first basic check.
- The session was made very short and simple by spending some time refining
  the `extract-model` skill. This makes some opinionated choices about code
  layout and dependencies that mean that the agent doesn't need to ask too
  many questions to produce a good result.

## Episode 2: Python continuation

- Planning transcript: [Python continuation planning](../../sessions/bs2026-python-continuation-planning/).
- The main task here was to reproduce Figure 1 from the paper, which shows
  some equilibrium curves for solutions to the ODE system.
- I wanted to use Python first for this because it's easier to inspect the
  code. I was planning to use the Python implementation as a reference for the
  other implementations.
- I had a surprisingly short grilling session about this, that mostly
  consisted of me saying "Yes" to the agent's choices. Things it did well were
  choosing log scales for some parameters ($n$, $q$ and the continuation
  parameter, which is the _log_ of the updraft velocity), and picking out the
  analytical/fitted equations from the paper to compare results against (that
  was without any prompting from me).

## What the agent was useful for here

One thing the agents are very good at is following a pattern, like the
"episode" setup I'm using here. This is the kind of thing that seems very
useful and a great idea when you first think of it when you're doing it
yourself, but that's very hard to stick to. If you do it by hand, keeping
everything in sync gets difficult quickly and you eventually just let it slide
and end up with something that kind of follows the pattern you wanted, but not
very accurately. The agents don't care if they have to make updates to half a
dozen files to keep things organized, and they can easily gather materials for
write-ups from all the different places it ends up.

In a similar vein, the agents can maintain discipline, writing documentation
as they go (how often do you do that yourself? I know that I don't!), keeping
track of the provenance of plots (no more undocumented notebooks floating
around containing the essential figures for your project).

Most importantly though, the agent can just plough very quickly through the
boring stuff. Struggling to set the problem up in LOCA is not scientifically
interesting, so it's nice to jump straight to the punchline, where you can
*see* how it's done.

And finally, doing the same thing three different ways in parallel and
cross-checking them helps to keep the agent honest and to avoid a whole class
of problems that could occur if you pushed this sort of thing forward using
just one set of tools.
