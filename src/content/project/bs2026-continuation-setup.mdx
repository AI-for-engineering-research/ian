- Goal of episodes 2–4:
  - Reproduce the Figure 1 equilibrium branch family.
  - Do it three ways: Python, AUTO-07p, and LOCA/Trilinos.
  - Start with an intentionally simple continuation problem.
  - Use the same problem as “training wheels” for backend setup.

- Why this is deliberately modest:
  - The first continuation target is not a dramatic bifurcation claim.
  - It is a branch-duplication and semantics-alignment exercise.
  - The question is: can three different systems reproduce the same equilibria?
  - Only after that should harder continuation tasks be trusted.

- Shared Figure 1 target:
  - `p = 300 hPa`.
  - `F = 1`.
  - `T ∈ {190, 210, 230} K`.
  - `w ∈ [0.005, 2.0] m s⁻¹`.
  - continuation coordinate: `log(w)`.
  - physical outputs: `n`, `q`, `s`.

- Important paper-detail trap:
  - Figure 1 does not state the aerosol number concentration in the caption.
  - The reproduction uses `N_a = 1.0e10 m⁻³`.
  - That value matches the Appendix A2 high-aerosol reference case.
  - The saturation-ratio panel is the clue that this value is needed.

- Python continuation:
  - Role: semantic reference implementation.
  - Advantage: transparent residuals, direct inspection, easy tests.
  - Output: branch CSVs, independent root-solve checks, Eq. 92–94 comparisons.
  - Use case: make the problem legible before introducing external continuation machinery.

- AUTO continuation:
  - Role: independent continuation backend.
  - Advantage: mature continuation machinery and familiar bifurcation-workflow conventions.
  - Cost: Fortran/run-file machinery and backend-specific output normalization.
  - Result here: close agreement with Python on the Figure 1 branches.

- LOCA/Trilinos continuation:
  - Role: third backend and infrastructure rehearsal.
  - Advantage: path toward larger Trilinos-based continuation experiments.
  - Cost: C++/CMake/toolchain setup and stricter interface discipline.
  - Result here: close agreement with Python and AUTO on the same branch family.

<VegaLite spec={residualSpec} caption="Backend agreement check using LOCA as the target branch and interpolating Python/AUTO references onto the LOCA grid." />

- Interpretation of the backend agreement plot:
  - These are solver-to-solver differences, not paper-digitization errors.
  - LOCA-vs-AUTO maximum relative differences are below about `8e-6` across `n`, `q`, and `s`.
  - LOCA-vs-Python differences are at the same numerical-continuation scale.
  - Digitized-paper comparisons are looser because pixel extraction is a different source of uncertainty.

- What this setup buys us:
  - A backend-neutral branch schema.
  - A common comparison pipeline.
  - Tests for residuals, Jacobians, branch fields, and output invariants.
  - A way to distinguish scientific disagreement from backend plumbing mistakes.

- What it does **not** prove yet:
  - It does not establish that one backend is best.
  - It does not reproduce every result in the paper.
  - It does not yet address harder bifurcation or periodic-orbit claims.
  - It only says the three tools agree on this training-wheels equilibrium task.
