This article covers episodes 2-4 in the
[repository](https://github.com/ian-ross/bergner-2026/tree/main/episodes). The
goal here was to reproduce [Figure 1 from the
paper](https://pubs.aip.org/view-large/figure/93440639/043115_1_5.0297531.figures.online.f1.jpg),
which is the first real numerical continuation result. It shows equilibrium
solutions across a range of model parameter choices. It's a simple
continuation problem to start with, simple enough that the agent asked me a
couple of times "are you sure you want to do this?", but it's a good test for
what I want to do.

What I'm doing here is using this simple problem as "training wheels" to get
the three continuation tools I want to use working, which are custom Python
continuation code, AUTO (which means reimplementing the model in Fortran) and
LOCA (which means reimplementing the model in C++). There is a lot of
machinery associated with using AUTO and LOCA, so having a simple problem to
start with helps to get that all set up.

The figure we're reproducing shows equilibrium solutions for $n$, $q$ and $s$
under three temperature conditions for three different updraft velocity
values. The traces for the Python, AUTO and LOCA calculations are essentially
indistinguishable and match the calculations in the paper (validated by
digitizing the curves in the paper figure).

<VegaLite spec={branchSpec} caption="Figure 1 branch duplication across Python, AUTO, and LOCA. The selector switches between $s$, $n$, and $q$; click Backend legend entries to enable or disable backends." />

The three continuation methods have different emphases here:

- **Python continuation**: This is intended as a sort of reference
  implementation, because it's the most transparent (at least for simple
  cases) and easy to inspect. At least to begin with, I'm mostly going to get
  the agent to implement this version of things first before looking at AUTO
  and LOCA.
- **AUTO**: This is an independent (and very old-school) continuation and
  bifurcation toolkit. Old-school means mature and well-tested, but it also
  means "not very easy to use". I've used it before and never liked it much,
  but wanted to use it as a kind of difficulty comparison case for seeing how
  much easier (if any) LOCA is to use.
- **LOCA/Trilinos continuation**: This is the system that I would use for
  working with larger systems. Trilinos is HPC-ready in a way that AUTO isn't.
  Again, not all that easy to use. Or so I thought. But then I saw the
  [automatic differentiation code for the
  Jacobian](https://github.com/ian-ross/bergner-2026/blob/c12afbfad2bb5fca5172ac4024e555d620a77109/loca/include/bergner_spichtinger_2026_loca/model.hpp#L216-L228)
  of the system for tracing the equilibrium branches. It's pretty
  nice.<Sidenote>One thing that's quite funny about the code that the agent
  wrote here is that it implemented its own Gauss elimination for solving the
  3×3 matrix in the Newton corrector. A 3×3 matrix is beneath the
  consideration of Trilinos...</Sidenote>

Comparing the results from the three solvers isn't that interesting in this
case, since it's a simple problem, but they are all very close:
